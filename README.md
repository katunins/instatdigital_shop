# Учебный магазин

Фронтенд оформления заказа: каталог, корзина, доставка, тестовая оплата картой или наличными. Бэкенд — в этом репозитории, менять его не нужно.

[Условия задания](docs/ASSIGNMENT.md) · [Работа с API](docs/INTEGRATION.md) · [Критерии оценки](docs/EVALUATION.md)

## Запуск

Нужны Node.js 24.x и npm 11.x.

```sh
npm ci
npm run dev
```

- API: [http://localhost:4000](http://localhost:4000), Swagger: [http://localhost:4000/docs/](http://localhost:4000/docs/)
- Фронтенд: [http://localhost:5173](http://localhost:5173)

По отдельности:

```sh
npm run dev:api
npm run dev:web
```

Сборка:

```sh
npm run build
npm start                 # собранный API
npm run preview -w @checkout/web
```

Адрес API для фронтенда по умолчанию — `http://localhost:4000`. Другой задайте в `apps/web/.env`: `VITE_API_URL=http://localhost:4100`.

Данные API: `.data/store.json`. Сброс: остановить сервер и `npm run data:reset`.

## Решение

SPA на Vite, React и TypeScript. Состояние — Redux Toolkit, запросы — RTK Query, UI — shadcn/ui и Tailwind. Типы ответов — из `@checkout/contracts`.

Интеграция с API сосредоточена вне страниц:

- [`apps/web/src/api/baseQuery.ts`](apps/web/src/api/baseQuery.ts) — единственное место с `fetch`: `baseUrl`, `Authorization`, `Idempotency-Key`, `Content-Type`, разбор JSON и ответов `204`.
- [`apps/web/src/lib/apiError.ts`](apps/web/src/lib/apiError.ts) — перевод кода ошибки и `fields` в тексты для интерфейса. Технические сообщения AJV на поля не выводим.
- [`apps/web/src/api/checkoutApi.ts`](apps/web/src/api/checkoutApi.ts) — endpoints. Новый запрос добавляется сюда, без копирования настройки соединения.
- Сессия, черновик формы, `orderId` / `paymentId` и ключи идемпотентности — слайсы + `redux-persist`. Повтор сети идёт с тем же ключом и телом; новая попытка оплаты получает новый UUID.

Страницы вызывают хуки RTK Query и экшены, а не `fetch`. Успех заказа берётся с `GET /api/orders/{id}`: для карты нужны `paid` и `succeeded`, для наличных показывается «Заказ оформлен, оплата при получении». Опрос оплаты останавливается при финальном статусе и при уходе со страницы.

## Проверенные сценарии

- Каталог из API, недоступный товар нельзя добавить, доступный попадает в серверную корзину.
- Количество меняется абсолютным `PUT`, позиция удаляется, итог совпадает с API.
- Самовывоз и курьер, контакты, сумма доставки и итог из quote.
- Карта: тестовые название и маска, ожидание, успех только после статуса заказа.
- Наличные: без онлайн-оплаты, сообщение об оплате при получении.
- Отказ карты и отмена различимы; повтор оплачивает тот же заказ новой попыткой.
- Двойной клик оформления и оплаты, повтор после сетевой ошибки — тот же Idempotency-Key.
- Перезагрузка восстанавливает сессию, корзину и заказ; незавершённая оплата продолжает опрос.
- Конфликт версии корзины и истекший quote: данные обновляются, форма не стирается.
- Пустую корзину оформить нельзя.

## Недоработки

- Нет автоматических e2e-тестов UI; проверки делались вручную.
- Условные запросы If-Match / ETag не используются — в задании не требуются.
